# 文書配置ガイド

`docs/` は、テンプレートから作成したリポジトリで利用する文書の配置先とする。テンプレートリポジトリへの貢献者向け文書は Wiki で管理する。

- `docs/` 直下には、この配置ガイドと文書種別ごとのサブフォルダーを置く。
- 一時的な調査結果は関連する恒久文書へ統合する。統合できない場合は Issue に残す。

## 文書種別

| フォルダー | 責務 | 配置する文書 |
| --- | --- | --- |
| `project/` | プロジェクト固有の目的と体制 | Problem Statement、Success Criteria、Definition of Done、ステークホルダー |
| `processes/` | 繰り返し実行する業務プロセス | Scrum の責務、Backlog 管理、イベントの進め方 |
| `policies/` | 守るべき規則と標準 | ブランチ保護、ラベル体系、Issue Template の使い分け、レビュー基準 |
| `guides/` | 特定作業の手順と学習資料 | セットアップ、機能選定、学習ガイド |
| `architecture/` | システム構造と技術判断 | アーキテクチャ概要、ADR、データフロー、外部連携 |
| `nfr/` | 検証可能な非機能要件 | セキュリティ、性能、信頼性、コスト、運用性の要件 |
| `operations/` | 稼働後の運用手順 | デプロイ、監視、障害対応、バックアップ、復旧手順 |

- 要件は `nfr/`、要件を満たす運用手順は `operations/` に分ける。

## 既存文書の棚卸し

| 配置 | 文書 | 分類結果 |
| --- | --- | --- |
| `processes/` | `backlog-management.md`、`scrum-accountabilities.md`、`scrum-ceremonies-agenda.md` | 繰り返し使う Scrum プロセス |
| `policies/` | `branch-policy.md`、`issue-templates.md`、`labels.md` | リポジトリで適用する規則と標準 |
| `guides/` | `setup.md`、`azure-learning-guide.md` | 作業手順と学習資料 |
| `nfr/` | `README.md` | NFR 文書の責務、標準ファイル、記載事項 |

- 重複: `setup.md` は規則の詳細を持たず、各ポリシーを参照するため重複なし。
- 分類上の課題: 解消済み。読者と文書種別の両方で配置を判断できる。
- 移動候補: なし。新しい責務が生じた場合は、既存文書への統合可否を先に確認する。
- `project/` はセットアップ Issue により文書が作成されるまで空とする。
- `nfr/` は配置ルールを示す `README.md` のみ置き、要件文書はセットアップ Issue で作成する。

## 追加・移動の判断基準

1. テンプレートから作成したリポジトリで使う文書かを確認する。貢献者向け文書は Wiki に置く。
2. 文書の主目的を標準構成の責務に照らして、配置先を 1 つ選ぶ。
3. 同じ目的の文書を検索し、追記または統合で済まない場合だけ新規作成する。
4. 主目的が異なる文書は分ける。
5. 移動時はリポジトリ内の相対リンクと自動生成 Issue の参照先を更新する。
6. 新しい分類が必要な場合は、文書を追加する前にこのガイドへ責務と対象を追記する。

## 命名規則

- ファイル名とフォルダー名は小文字の kebab-case にする。
- ファイル名は内容を表す名詞句にし、`document.md` や `misc.md` を避ける。
- 日付や版番号は履歴管理に Git を使い、原則としてファイル名に含めない。
- 同じ主題を複数ファイルに分割する場合は、主題名のサブフォルダーを作り、その中に `README.md` を置く。

## レビュー観点

- 標準フォルダーの責務と文書の主目的が一致しているか。
- テンプレート利用者向け文書であり、貢献者向け Wiki に置く内容ではないか。
- 既存文書への追記や統合ではなく、新規文書が必要か。
- 要件、設計、運用手順が 1 文書に混在していないか。
- 相対リンク、README、Issue テンプレート、Copilot 指示の参照先が有効か。
- 将来も使う決定だけが残り、一時的な議論や作業メモが混入していないか。
